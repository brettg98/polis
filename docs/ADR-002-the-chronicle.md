# ADR-002: The Chronicle and its Viewer

Date: 2026-07-25
Status: accepted

## Context

The tournament produces the headline chart, but the credibility of a behavior
benchmark rests on receipts: what did each model say, promise, deliver, and
privately write to itself, tick by tick? Today the engine discards diplomatic
messages after delivery and keeps only each seat's final journal; the full
story survives only in per-seat call logs never meant for readers. Brett's
reference point is Dwarf Fortress's Legends mode: a world's complete history,
browsable as local HTML.

Decided in a grill-me session, 2026-07-25. Terms defined in CONTEXT.md.

## Decision

1. **Record everything, and call it the Chronicle.** Per rotation, a complete
   post-hoc record: outcomes, structured events, the full diplomatic message
   transcript (engine gains a message log), per-tick journal snapshots and
   stockpile/population series (runner-captured), and offer/agreement
   lifecycles. Raw call logs (prompts, retries, provider noise) stay out.
2. **Observer-omniscient after the fact.** The Chronicle publishes what was
   private in-game — journals, messages — because the run is over. It never
   feeds back into seats, and seats are not told it exists.
3. **The Viewer is one self-contained HTML file per tournament**, generated by
   the tournament runner and regenerable standalone (`npm run chronicle`).
   Data inlined, no server, works from file://. Tournament front page
   (masthead, cross-rotation results, rotation cards); per-rotation views:
   event timeline, per-city journal scrubber, diplomatic cables (per-pair
   messages interleaved with deliveries/defections), population chart. Map is
   a canvas top-down render of the inlined heightmap with trade-weighted
   links, palette-matched to the 3D sim.

## Consequences

- The engine records a message transcript; the runner snapshots journals and
  stockpiles per tick. These must land BEFORE the full tournament — a
  rotation run without them cannot be backfilled into a Chronicle.
- Chronicles are a few MB of JSON per rotation; the Viewer inlines them.
- The published artifact shows models' private reasoning verbatim; the writeup
  should say so plainly (it is the point, not a leak).
- The 3D renderer is not reused in the Viewer; replay-on-the-map is a
  separate deferred feature, not a Viewer requirement.

## Rejected

- Viewer as a page in the vite app (couples the artifact to build + hosting +
  data paths; single file is more durable and more shareable).
- Minimal recording (events only) — kills the journal scrubber and cables,
  which are the artifact's identity.
- Embedding 3D screenshots in the Viewer (breaks headless regeneration).

## Revisit when

The Viewer needs replay animation, cross-tournament comparison, or chronicle
sizes make single-file impractical.
